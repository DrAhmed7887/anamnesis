# Spark's claim prompt adds one sentence for combination products (SPEC §2, "Prompts", batch 29)

You are the builder for batch 29 of Anamnesis. Read SPEC.md §2, the "Prompts" bullets, first: the new one, "Spark's claim prompt adds one sentence (batch 29)", is the specification. The contract tests are `tests/contract/test_b29_combination_prompt.py`.

## Why
U2 ("I take Augmentin, 875 and 125 milligrams, twice a day") misses live because Spark 1.3 writes no amount, or "875 and 125" as one string, for a combination said as two numbers. One sentence in Spark's prompt fixes it in a pilot. The tuned Glimmer must keep the exact prompt it was trained on.

## Build
1. **In `anamnesis/providers/claims.py`:** a module constant with the SPEC's sentence, word for word, and Spark's prompt built as `_SYSTEM_PROMPT` + a space + that sentence. `MetaClaimExtractor` sends Spark's prompt as its system message. `_SYSTEM_PROMPT` itself doesn't change, so `glimmer.py` and `finetune/common.py`, which build on it, don't either.
2. **Your own tests** go in `tests/unit/test_b29_extra.py`.

## Hard rules
1. **Locked files:** never create, modify or delete anything under `tests/contract/`, any `conftest.py`, `pyproject.toml` or `uv.lock`. Add no dependency.
2. **Off limits:** don't edit `SPEC.md`, `docs/`, `evidence/`, `briefs/`, `NOTICE`, `finetune/` or any script. Don't open anything under `evidence/` or `finetune/data*`.
3. **Behaviour that stays:** `_SYSTEM_PROMPT`, the claims schema, the checks, the Glimmer extractor and every earlier contract.
4. **No outside contact:** no network, no API keys, no `modal` commands, no git commits.
5. **Tools:** run them as `.venv/bin/ruff` and `.venv/bin/python -m pytest`. One test needs a local network socket that your sandbox forbids; if it is the only failure, say so and close your goal.

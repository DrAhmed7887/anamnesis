# Amounts must be stated, and the clinician signs off after an optional photo request (SPEC §2, §7, §8)

You are the builder for batch 20 of Anamnesis (Python 3.12, uv), a pre-visit medication-intake tool that reports where a patient's spoken account and the photos of their medicine packs disagree, and never gives advice. Two changes come from Meta's legal-agent workshop of 27 Oct: refuse any number the source doesn't state, and let a person pause the intake for one new piece of evidence and then sign off. Keep the batch focused: no refactors outside what this brief names.

## Goal
Make `tests/contract/test_b20_stated_amounts.py` and `tests/contract/test_b20_review.py` pass, together with `tests/contract/test_b16_model_replies.py` (amended for this batch: two of its number tests now cite a turn that says the number), and keep every other test green. Read SPEC.md first:
- §2 "Amounts must be stated" (all of it);
- §8 "Clinician review and photo requests" (all of it);
- the §7 lines marked "batch 20";
- §4, for the loop steps that `add_photo` reuses.

## Changes
1. **`stated_amounts(text) -> frozenset[Decimal]`**, exactly as SPEC §2 says: digits through `parse_amount_text`, then the English and Arabic number words on the tokens of `catalogue.normalise(text)`, with runs, hundreds, thousands, halves, `point` decimals and an attached `و`. Keep the word tables as module constants, written as the SPEC lists them (already normalised: `ه` for `ة`, `ا` for `أ`).
2. **Claims.** In `parse_claims_json`, after the amounts are parsed, null each `strength` whose ingredient amounts aren't all in the union of `stated_amounts` over the claim's cited turns, and each `intake_amount` whose amount isn't. Do it **before** the "a dropped claim amount takes the other one with it" rule, so that rule handles the other field. Compare Decimals by value (`Decimal("2.50") == Decimal("2.5")`). Regimen numbers are not checked. Add the sentence "Write each amount with the number and unit the patient said, and never convert units." to the claim `_SYSTEM_PROMPT`, before "Give no medical advice."
3. **Labels.** In `parse_label_json`, after `coerce_strength`, set the strength to null unless every ingredient amount is in `stated_amounts(label_text or "")`. The reading itself is kept. Add "Write each amount with the number and unit printed on the pack, and never convert units." to the label `_SYSTEM_PROMPT` in `meta.py`, before "Give no advice." The Spark estimate counts prompt text, so the estimate tests compute their expected values from the body; keep them green.
4. **Review models** (`anamnesis/schema/review.py`, all `extra="forbid"`): `RequestKind`, `RequestStatus`, `ReviewStatus` (`StrEnum`, values as in SPEC §8), `PhotoRequest`, `Review`, with the validators SPEC §8 lists (`photo_index` set exactly when answered; `awaiting_patient` exactly when a request is open, which also means an approved review has none open; `intake_id` 64 lowercase hex).
5. **`ReconciliationReport.superseded: list[str]`**, default empty. Extend `check_references` so each id must be an existing observation and no finding may cite one. Older reports without the field still validate.
6. **`anamnesis/review.py`**, as SPEC §8 says, function by function. Notes:
   - Every function returns new objects; never mutate the report or the review you were given.
   - Check every refusal before any model call, and raise `ValueError` with a short message.
   - `add_photo` must reuse the loop's own steps (`_prepare`, `_read_photo`, `_zoom`, `_observation`, `_intake_id`, `IntakeSession`) rather than copying them. Undecodable photos log the same step as in the loop.
   - New step numbers continue from the last `n`.
   - The answered `unreadable` target goes into `superseded` **only when the new photo gave at least one observation**, and reconciliation then runs on the claims and the observations that aren't superseded.
   - `request_message` text comes from `templates.py`.
7. **The brief.** `render_brief(report, images, audio, catalogue, review=None)`:
   - the `<p id="review-status">` line inside the `scope` header;
   - the `<p data-request="<request_id>">` line inside each finding article that an open request targets (an `unreadable` request targets the finding with that `observation_id`; a `not_photographed` one targets the claim-only finding of that `claim_id`);
   - "Replaced by a newer photo." in the region figure of each superseded observation's region;
   - the "Photos requested {n}, received {m}." coverage line, only when a request isn't withdrawn;
   - a review whose `intake_id` isn't the report's is refused with `ValueError`.

   `coverage_lines` keeps its signature. All new fixed text goes in `templates.py` with the exact SPEC strings and must pass `assert_no_advice`. Escape every source string as before (the claim's `name_text` in `request_message` is plain text, not HTML, so it is not escaped there).
8. **Unit tests.** Put your own in `tests/unit/test_stated_extra.py` and `tests/unit/test_review_extra.py`. Keep each new file under about 400 lines.

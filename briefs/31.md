# The follow-up runs by itself (SPEC §8, batch 31)

You are the builder for batch 31 of Anamnesis. Read SPEC.md §8 first, with its new subsection "The follow-up by itself (`follow_up`, batch 31)": it is the specification. The contract tests are `tests/contract/test_b31_follow_up.py`.

## Why
Today the clinician starts each photo request by hand (`anamnesis/review.py`, `request_photo`). The follow-up asks the patient for every photo the brief is missing, takes the replies through `add_photo`, and leaves a draft that the clinician approves. Code fixes the targets, their order and when to stop. No model chooses anything, and every message to the patient is a template.

## Build
1. **In `anamnesis/schema/review.py`:** `FollowUpOutcome` (a `StrEnum`: `answered`, `no_reply`, `duplicate`) and `FollowUpStep` (`extra="forbid"`: `round` at least 1, `request_id`, `target_id`, `kind` a `RequestKind`, `outcome`).
2. **In `anamnesis/schema/templates.py`:** `FOLLOW_UP_DONE`, exactly as SPEC gives it.
3. **In `anamnesis/review.py`:** `follow_up(...)`, as SPEC specifies it:
   - check every refusal before anything else;
   - a round's targets are the `requestable(report)` entries pending at the round's start, each re-checked before it is asked;
   - call `reply` once per request, after `request_photo` has opened it;
   - answer a photo through `add_photo`, and turn its "photo was already given" refusal into `duplicate`;
   - leave the request open for `no_reply` and `duplicate`;
   - keep the growing image list, and the log.

   Build it from the existing functions, and don't change how any of them behaves.
4. **In `anamnesis/brief.py` and `brief_html.py`:** `render_brief(..., review=None, follow_up=None)`, the `<p id="follow-up">` line in the scope header, and its refusals.
5. **Your own tests** go in `tests/unit/test_b31_extra.py`.

## Hard rules
1. **Locked files:** never create, modify or delete anything under `tests/contract/`, any `conftest.py`, `pyproject.toml` or `uv.lock`. Add no dependency.
2. **Off limits:** don't edit `SPEC.md`, `docs/`, `evidence/`, `briefs/`, `NOTICE`, `finetune/` or any script. Don't open anything under `evidence/` or `finetune/data*`.
3. **Behaviour that stays:** every earlier contract, every existing function in `review.py`, and the brief without a follow-up log.
4. **No outside contact:** no network, no API keys, no `modal` commands, no git commits.
5. **Tools:** run them as `.venv/bin/ruff` and `.venv/bin/python -m pytest`. One test needs a local network socket that your sandbox forbids; if it is the only failure, say so and close your goal.

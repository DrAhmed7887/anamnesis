## Changes
1. **`OpenWeightClient(api_key, base_url, provider, transport=None, timeout=60.0)`.** An OpenAI-compatible HTTP client with exactly `MetaClient`'s behaviour:
   - Bearer auth;
   - the same retryable and billable-uncertain classes;
   - the API key redacted from every message;
   - malformed JSON handled the same way.

   Its `ProviderError`s name `provider` (`"fireworks"` or `"baseten"`) instead of `"meta"`. Reuse `MetaClient`'s code, by subclassing or a small shared helper, without changing anything `MetaClient` does.
2. **`PRESETS`:**
   - `{"fireworks": {"base_url": "https://api.fireworks.ai/inference/v1", "model": "accounts/fireworks/models/muse-spark-open", "json_mode": True}`
   - `"baseten": {"base_url": "https://inference.baseten.co/v1", "model": "meta-models/muse-spark-open", "json_mode": False}}`
3. **`OpenWeightLabelReader(client, guard, *, model, price_key, json_mode)`.** It has the same `read(image, region, *, mime, cropped=False)` as `MetaLabelReader`.
   - **The same messages:** import `_SYSTEM_PROMPT` from `anamnesis/providers/meta.py`, and use the same user text and image part. Send `"max_tokens": 4000` and no `reasoning_effort`.
   - **With `json_mode`:** the same `response_format` as `MetaLabelReader`.
   - **Without it:** no `response_format`. The user text gets one more sentence: `"Reply with only one JSON object that matches this JSON schema: " + json.dumps(LABEL_SCHEMA, sort_keys=True)`. Before parsing, strip one surrounding ```` ``` ```` or ```` ```json ```` fence.
   - **The same parsing and checks:** parse with `parse_label_json`, so the shape check, the advice check and the "amount printed on the label" rule all apply unchanged.
   - **The same control flow:** `spark_call_estimate`, `guard.check` before the request, `charge_prechecked` after it, the length stop (not retried) and `with_one_retry`.
   - **The estimate:** `spark_call_estimate` prices by `body["model"]`. So estimate on a copy of the body whose `model` is `price_key`, and send the real model id.
   - **Naming:** the trace and the ledger name the model as `price_key`, for example `"muse-spark-open@fireworks"`.
   - **Refusal:** a `model` ending in `-contributor` raises `ValueError`.
4. **Prices** (`_PRICES`): `"muse-spark-open@fireworks"` and `"muse-spark-open@baseten"`, each $1.25 per 1M input tokens and $4.25 per 1M output tokens.
5. **One number word as the whole amount** (`parse_amount_text`). When the stripped text is one token that is not digits, normalise it with `catalogue.normalise`, then:
   - **Parse** a plain number word, English or Arabic, or a one-word Arabic hundred (`_combined_hundreds`), worth more than 0: that value is the amount.
   - **Reject** everything else: two or more tokens, zero, half, hundred and thousand words, and "once"/"twice".
   - **Avoid a cycle:** the number tables live in `anamnesis/providers/stated.py`, which imports `parse_amount_text`. Import them inside the function, or move them to a module both can import, without changing what `stated_amounts` does.
   - **What it fixes:** live, Spark wrote `"amount": "five"` for "Norvasc five milligrams", and the dose was dropped (`evidence/batches/21/live-after.md`, U5). The stated-amount check is unchanged.

`tests/contract/test_b16_model_replies.py` changed in this batch's contract commit. Its case for the word "two" now expects 2. That was the CEO's edit, made with item 5; leave it as it is.

## Changes
1. **One ingredient resolver** in `anamnesis/core/reconcile.py`, used by **every** ingredient field: `strength.ingredients[].inn`, the scalar `inn` and `intake_amount.inn`.
   - The resolver takes a raw name and returns a canonical moiety:
     - `canonical_inn(name)` when it's a known catalogue moiety;
     - otherwise, the INN of a single-INN catalogue entry that the name resolves to (a brand such as "concor");
     - otherwise, `canonical_inn(name)` unchanged. Unknown stays unknown and surfaces downstream.
   - `_identity` uses it for strengths **and** for the scalar `inn`. When a scalar `inn` is given and `name_text`/`label_text` also resolves, a different INN set is an extraction conflict (F-03b).
   - `_intake_type` and `_pair_score` use the same resolver. Remove the batch 9 special case inside `_intake_type`.
2. **Known conflicts first (F-01).** Insert a rule after "discontinued" and before any amount comparison: `formulation_mismatch` when
   - both sides name a salt for the same canonical ingredient and the salts differ, or
   - both release forms are known (explicit, otherwise brand-implied) and differ.

   Claim salts come from `strength` ingredients, `intake_amount.salt` and `salt_of(claim.inn)`. Pack salts come from `strength` ingredients and `salt_of(pack.inn)`. The final "one side modified, the other unknown → `insufficient_information`" gate stays where it is, before `match`.
3. **`anamnesis/core/catalogue.py`**
   - **F-08:** record each match's character span with `re.finditer`. A match is suppressed only when its span lies **inside** another, longer match's span. Two separate mentions of different products → `None`.
   - **F-02:** a brand match covers non-brand (INN or alias) matches whose INN set is within that brand's INNs. If only INN or alias matches remain and they all share one INN set, return one entry deterministically (sorted by brand). Brand-implied facts (`implied_release`, `splittable`) still need a **brand** match.
4. **`SPEC.md` §3:** describe the new rule order, the single resolver, and span-based containment.
5. Your own unit tests in `tests/unit/test_identity_extra.py`.

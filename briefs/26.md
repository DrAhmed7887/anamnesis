# Open weights inside the product: the tuned Glimmer on Modal extracts claims and Spark Open on Fireworks reads labels, both optional (SPEC §4)

You are the builder for batch 26 of Anamnesis. Read SPEC.md §4, "Open-weight claim extractor and the Fireworks reader (batch 26)", first: it is the specification. The contract tests are `tests/contract/test_b26_open_weight_path.py`.

## Why
- **Two open-weight models are evaluated, but neither runs in the product.**
  - A LoRA adapter on Meta's open-weight Muse Glimmer 30B (run "r1") was trained and scored on Modal by `finetune/modal_glimmer.py`. On 303 generated test notes it was fully right on 290, with 0 harmful claims after the product's checks; Spark 1.3 was fully right on 203.
  - Muse Spark Open reads pack labels through `OpenWeightLabelReader`, but `scripts/intake_live.py` offers it only on Baseten, which we no longer use.
- **This batch adds both as options.** Without a flag, nothing changes.

## Build
1. **The price** (`anamnesis/providers/base.py`):
   - `_PRICES["muse-glimmer-30b+lora-r1@modal"] = {"gpu_seconds": Decimal("0.00127284")}`;
   - `cost_usd(..., gpu_ms: int | None = None)`: the seconds rounded up, as audio is, so 1 ms costs one second and 0 ms nothing; a negative `gpu_ms` raises `ValueError`;
   - every other price and call stays as it is.
2. **The extractor** (new, `anamnesis/providers/glimmer.py`):
   - **Constants:** `GLIMMER_MODEL_ID = "muse-glimmer-30b+lora-r1@modal"`, `GLIMMER_TIMEOUT_S = 120.0`, and the system message, `_SYSTEM_PROMPT` plus `"\nReasoning strength: low"`.
   - **`GlimmerClaimExtractor(client, guard)`,** with `extract(turns) -> tuple[list[PatientClaim], ProviderTrace | None]`:
     - no turns: return `([], None)` and make no call;
     - the user message is built exactly as `MetaClaimExtractor` builds it. If you factor that join into a helper both use, `MetaClaimExtractor`'s request must stay byte-identical;
     - the request: `client.post("/extract", json={"messages": [system, user], "schema": CLAIMS_SCHEMA, "max_tokens": 16000})`;
     - the estimate: `cost_usd(GLIMMER_MODEL_ID, gpu_ms=int(GLIMMER_TIMEOUT_S * 1000))`, passed to `guard.check` before the request and to `with_one_retry`.
   - **Validating the reply:** it must be an object with all seven fields:
     - `id` (a non-empty string);
     - `reply` (a string or null);
     - `opened_answer` (a bool);
     - `first_finish` and `answer_finish` (a string or null);
     - `prompt_tokens` and `completion_tokens` (ints, not bools, 0 or more).

     Anything else is malformed: raise a retryable `ProviderError("modal", ...)` with `billable_uncertain=True`, before any trace, as `MetaClaimExtractor` does for a malformed Spark response.
   - **Then, in this order:**
     1. build the `ProviderTrace`: `call_id` = `id`, the model `GLIMMER_MODEL_ID`, the client's latency, the two token counts, and cost `cost_usd(GLIMMER_MODEL_ID, gpu_ms=latency_ms)`. Charge it with `guard.charge_prechecked`;
     2. if `first_finish` or `answer_finish` is `"length"`, raise a non-retryable error with `attempt_trace=trace`;
     3. if `reply` is null, raise a retryable error with `attempt_trace=trace`;
     4. run `parse_claims_json(reply, turns)`. On its `ProviderError`, raise a retryable error with `attempt_trace=trace`, its message passed through `client._safe`.
   - Every error this class raises names the provider `"modal"`. HTTP errors come from `OpenWeightClient`, which already names its provider and redacts the key.
3. **The live script** (`scripts/intake_live.py`):
   - **Options:**
     - `--reader` takes `spark`, `baseten` or `fireworks`;
     - a new `--extractor` takes `spark` (the default) or `glimmer`;
     - a new `--glimmer-url`, which defaults to the `GLIMMER_URL` environment variable.
   - **`Run` gains `glimmer_client: OpenWeightClient | None = None`.**
     - In `intake()`, an open-weight reader is built from `PRESETS[run.open_client.provider]`'s model, with `price_key=f"muse-spark-open@{provider}"` and `json_mode=False` for both providers. `PRESETS` itself doesn't change.
     - When `run.glimmer_client` is set, the extractor is `GlimmerClaimExtractor(TimedClient(run.glimmer_client), guard)`.
     - The `runs.jsonl` line records `"reader"` (`spark`, `baseten` or `fireworks`) and `"extractor"` (`spark` or `glimmer`). The printed line gives the extractor client's real timeout.
   - **The guards,** all in `main()` before any key is read or any client is built:
     - `--reader fireworks` needs `--case`, and refuses any photo outside `OPEN_WEIGHT_PHOTOS`, exactly as `--reader baseten` does. Its messages contain `--case` and `may go to Fireworks`.
     - `--extractor glimmer` needs `--case` (the message contains `--case`).
     - Its `--voice`, resolved, must lie under `evidence/raw/media/public/voice/` (`MEDIA / "public/voice"`). Otherwise the message contains `may go to Modal`.
     - Its URL must exist, start with `https://`, and have a host ending in `.modal.run`. Otherwise the message contains `modal.run`.
   - **The clients:**
     - Modal: `OpenWeightClient(api_key=os.environ.get("MODAL_PROXY_TOKEN") or keychain("MODAL_PROXY_TOKEN"), base_url=url, provider="modal", timeout=GLIMMER_TIMEOUT_S)`;
     - Fireworks: `OpenWeightClient(api_key=os.environ.get("FIREWORKS_API_KEY") or keychain("FIREWORKS_API_KEY"), base_url=PRESETS["fireworks"]["base_url"], provider="fireworks")`.
   - **The docstring** lists the new options.
4. **The server** (new, `finetune/modal_serve.py`):
   - **The app:** a Modal app `anamnesis-glimmer-serve` that imports `modal_glimmer` (add `HERE` to `sys.path` as `modal_glimmer.py` does). Its image is `modal_glimmer.eval_image` plus `modal_glimmer.py` at `/root/modal_glimmer.py`.
   - **The class:** `@app.cls(image=..., gpu=glimmer.GPU, timeout=600, scaledown_window=600, max_containers=1, **modal_glimmer.MACHINE)`, named `Server`.
   - **`@modal.enter()`** reloads the runs volume, then loads one engine with exactly `evaluate`'s settings:
     - `LLM(model=modal_glimmer.WEIGHTS, enable_lora=True, max_lora_rank=glimmer.LORA["r"], max_loras=1, max_model_len=glimmer.MAX_MODEL_LEN, limit_mm_per_prompt={"image": 0, "video": 0}, seed=glimmer.EVAL_SEED)`;
     - its tokenizer, and `LoRARequest("r1", 1, "/runs/r1/adapter")`.
   - **`@modal.asgi_app(requires_proxy_auth=True)`** returns a FastAPI app with two routes:
     - `GET /health` returns `{"ready": true, "adapter": "r1", "revision": glimmer.REVISION}`;
     - `POST /extract` checks the body. It needs:
       - `messages`, exactly a system and a user message with non-empty string contents;
       - `schema`, an object;
       - `max_tokens`, an int from 1 to 16000.

       A bad body gets a 400. Then it runs `modal_glimmer._two_passes(self.llm, self.tokenizer, [messages], self.lora, schema, max_tokens)` unchanged, on that one conversation. It returns the seven fields of SPEC §4:
       - `id` a fresh `uuid4().hex`;
       - `reply`, `opened_answer`, `first_finish` and `answer_finish` from the row, with `answer_finish` null when no answer was written;
       - `prompt_tokens`, the length of `glimmer.prompt_ids(tokenizer, messages)`;
       - `completion_tokens`, `first_tokens` plus `answer_tokens`.
   - **Nothing else:** no `min_containers`, and nothing runs at import beyond defining the app. The module docstring gives the deploy command (`~/.local/bin/modal deploy finetune/modal_serve.py`) and a warm-up: `GET /health` with the token, waiting up to 10 minutes.
   - **No test imports this file,** because `modal` isn't installed in the venv. Keep its logic in the routes thin.

# No catalogue codes beside a side that contradicts its own name (SPEC §7)

You are the builder for batch 24.2 of Anamnesis (Python 3.12, uv). Anamnesis is a pre-visit medication-intake tool: it reports where a patient's spoken account and the photos of their medicine packs disagree, and it never gives advice. Keep each change surgical: no refactors, and nothing outside this brief.

## Goal
Make `tests/contract/test_b24_2_codes_conflict.py` pass, and keep every other test green. First read the SPEC.md line marked "batch 24.2", in §7 "Catalogue codes".

## The change (`anamnesis/brief_html.py`, and `anamnesis/core/reconcile.py` if you need a public helper)
1. **A finding box shows its catalogue codes only when that side agrees with its own name.**
   - **The claim side:** use the reconciler's own identity check for a claim, `_claim_identity` in `core/reconcile.py`. It compares the claim's name, its stated INN and its strength's ingredients, and returns a conflict flag. When the flag is set, the box shows no codes line.
   - **The pack side** (a finding with no claim): use `_pack_identity`, which also takes the pack's country. When its flag is set, no codes line.
   - **The rule:** don't write a second comparison. Reuse the reconciler's, through a small public wrapper if you prefer not to import private names.
2. **The reference line** still appears once per page when any codes line is shown, and never otherwise. That is batch 24.1's rule, and it now counts only the codes lines that remain.

**The failure:** a claim named "Concor" with the stated ingredient "atorvastatin" showed bisoprolol's codes beside the patient's atorvastatin.

**What must keep working:** every batch 24.1 contract test. A side whose ingredient agrees with its name keeps its codes.

## Unit tests
Put your own tests in `tests/unit/test_b24_2_extra.py`. Cover a combination product (Panadol Extra) whose stated strength names only one of its ingredients, and say in the test name what the brief shows.

## Rules
- **Never create, modify or delete anything under `tests/contract/`, any `conftest.py`, `pyproject.toml` or `uv.lock`. A batch that touches them is rejected automatically.** A contract test that is skipped or xfailed fails the gate too.
- Don't edit `SPEC.md`, `scripts/`, `evidence/`, `docs/`, `NOTICE` or `finetune/`.
- Work only inside this repository. No network, no API keys, no git commits, no new dependencies.
- `uv` can't write its cache in your sandbox, so run the tools as `.venv/bin/ruff` and `.venv/bin/python -m pytest`.
- **One test needs a local network socket that your sandbox forbids.** If it is the only failure, say so and close your goal. The gate runs outside the sandbox.

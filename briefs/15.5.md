# Phone photos keep their provenance: upright pixels, no metadata, regions read only from their own photo (+ QM M3 r2 #1)

You are the builder for batch 15.5 of Anamnesis (Python 3.12, uv), inserted before B16 (the clinician brief). **Keep it small and surgical**: no refactors, no new features beyond this brief.

## Why
A live run on staged 12 MP phone photos (`evidence/live/2026-10-27/zoom_before/summary.md`) showed that SAM applies a photo's EXIF orientation (it returned a 3024×4032 frame for a portrait photo stored as 4032×3024) while Spark reads the stored sideways pixels. On the portrait photo, 2 of 3 labels were read from the **wrong pack**, and one pack was never read. Offline, the current crop-zoom refuses every 90° photo (`error: crop failed`) and, on a 180° photo, crops the wrong pixels while keeping the region id. Phones write exactly these files.

## Goal
Make `tests/contract/test_b15_5_zoom.py` pass, keeping all other tests green. SPEC §4 (step 0, step 4 and the budget rule) is already updated: read it first.

## Changes
1. **New `anamnesis/agent/media.py`** with `prepare_image(data: bytes, mime: str) -> tuple[bytes, str]`, exported from `anamnesis.agent` (add it to `__all__`).
   - Decode with Pillow. Bytes that can't be decoded raise `ValueError`.
   - If the photo has no EXIF orientation other than 1 and carries no metadata (no EXIF at all, no XMP), return `(data, mime)` unchanged, byte for byte.
   - Otherwise apply the orientation (`ImageOps.exif_transpose`) and re-encode **without any metadata**: JPEG stays JPEG (quality 95, `subsampling=0`), anything else becomes PNG; the returned mime matches the format. Make sure nothing from `info` (EXIF, XMP, GPS) is carried into the new file.
   - It must be deterministic and idempotent: `prepare_image(*prepare_image(x, m)) == prepare_image(x, m)`.
2. **`run_intake`** prepares every photo first and uses only the prepared bytes and mime from then on (SAM, every read, the crop, `intake_id`).
   - A photo that raises `ValueError` while preparing: log one `segment` step whose outcome is exactly `error: image cannot be decoded` (no call ids, no provider call, no spend), skip it, go on with the next photo. Not after `budget_exhausted` (see 4).
3. **Read only from the source photo.** Before reading a region, check that its `image_sha256` equals the sha256 of the prepared bytes and that `(frame_w, frame_h)` equals the prepared photo's size. If not, log a `read` step with outcome exactly `error: region does not match the photo` and skip that region (no read, no zoom). Decode each photo's size once, not per region.
4. **QM M3 round 2 #1:** once `budget_exhausted` has been logged, nothing else is ever appended to the steps: not a failed crop in `_zoom`, not the new errors from 2 and 3. `_zoom` returns the original reading without cropping when the session is exhausted. Keep calling the crop through the name `crop_region` imported into `anamnesis/agent/loop.py` (the contract patches `anamnesis.agent.loop.crop_region`).
